The quick score looks for surface signals only (a named deliverable, numbers and file names, limits, a format, a check). It cannot know whether your facts are the right ones. Claude can.

Claude Code

Install the skill

Inside Claude Code the same workflow can read your project first. It pulls the real test command, the file your draft points at, the rules in CLAUDE.md, and an existing example to imitate, then grades, asks a batch of questions, and rewrites. That substitution of your project's facts for generic nouns is where most of the gain comes from.

  1. Install. Clone the repo and link the skill into your user skills folder:
git clone https://github.com/jiaqi01pd2027-dotcom/Prompt-Engineer.git
ln -s "$(pwd)/Prompt-Engineer/skill/prompt-engineer" ~/.claude/skills/prompt-engineer
  1. Use. In any Claude Code session: /prompt-engineer fix the login bug, or paste a prompt and say "grade this". It also triggers when you ask "how should I ask for X".
  2. Pick a rewrite. A is minimal, B is structured with your project's facts, C is the interview or agentic form. The skill says which it recommends and why.

Cheat sheet

The patterns, ranked

What to add to a prompt, in the order it pays off. Each card has the phrasing, when it helps, when it hurts, and the evidence.

Ration or avoid

Tips, threats, and emotional appeals: no reliable gain on 2025 models and high per-question variance. ALL CAPS, "CRITICAL", stacked "always" and "never": current Claude models over-trigger on them, and emphasis spent everywhere is emphasis spent nowhere. Contradictory rules: the top failure mode named by both Anthropic and OpenAI. Politeness or rudeness as a lever: the sign flips between models and years.

The evidence

What 360 runs showed

Twelve tasks across six domains, each written in ten phrasings that keep the job fixed, each run fresh on three Claude models, scored blind on five dimensions.

    See the difference

    Two prompts for the same customer complaint, same model, nothing else in the context. Real outputs from the experiment, unedited.

    How to read this

    One run per cell means single-task numbers are noisy; read the pattern and domain averages, not one task. The judge is a Claude model scoring Claude outputs, so absolute scores are less trustworthy than the ordering. Objective checks (exact answers, JSON validity, word limits) back the ordering where the task allowed them. Human ratings from the rating page are collected separately and never mixed into these charts.
