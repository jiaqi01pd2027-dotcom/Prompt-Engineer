## Implementation plan: optional `due_date` + `overdue` filter

### 0. Decisions locked in (from your answers)
- `due_date` is optional/nullable, a datetime. Accepted as ISO-8601 with or without offset; naive values mean UTC; everything is stored and returned as UTC.
- Overdue = `due_date IS NOT NULL AND due_date < now_utc AND done = false`.
- API: `due_date` on POST/PATCH bodies and in every response; `GET /todos?overdue=true`, ANDed with the existing `done` filter.
- One decision left for the developer, defaulted here: `overdue=false` returns the complement (done, or no due date, or due in the future), mirroring how `done=false` behaves. Omitting the param applies no filter.

### 1. `app/models.py` — column plus a UTC-normalizing column type
1. Add a small `TypeDecorator` (e.g. `UTCDateTime`, wrapping `DateTime`) in this file. Reason: SQLite has no timezone-aware datetime, so SQLAlchemy's `DateTime` drops the offset on write and returns naive values on read. The decorator must:
   - On bind: if aware, convert to UTC; if naive, treat as UTC; hand SQLite a naive UTC value.
   - On result: re-attach `tzinfo=UTC` so every datetime in the app is aware.
2. Add `due_date` to `Todo`: `UTCDateTime`, `nullable=True`, no default.
3. Leave `created_at` alone (out of scope), but note it is a candidate for the same decorator later.

### 2. `app/schemas.py` — request/response fields and normalization
1. `TodoCreate`: add `due_date: datetime | None = None`.
2. `TodoUpdate`: add `due_date: datetime | None = None`. Clearing must work, so the PATCH route will rely on "field was explicitly set" rather than "field is not None" (see step 3.2).
3. Add one shared field validator (mode "after") used by both create and update: naive input gets `tzinfo=UTC`; aware input is converted to UTC. Pydantic already parses ISO-8601 strings, so invalid strings return 422 for free.
4. `TodoOut`: add `due_date: datetime | None`. Because the model returns aware UTC values, the JSON output will carry a `+00:00`/`Z` suffix. Confirm `from_attributes`/ORM mode is already on.

### 3. `app/routes.py` — pass-through, clear-on-null, and the filter
1. POST `/todos`: pass `due_date` from the body to the model constructor.
2. PATCH `/todos/{id}`: build the update dict with `model_dump(exclude_unset=True)` so that
   - omitted `due_date` leaves the value unchanged,
   - explicit `"due_date": null` clears it,
   - a value sets it.
   Check how `title`/`done` are currently applied; if the existing code does `if body.done is not None`, switch the whole handler to the `exclude_unset` approach rather than special-casing `due_date`.
3. GET `/todos`: add query param `overdue: bool | None = None`.
   - Compute `now = datetime.now(timezone.utc)` once per request inside the handler.
   - `overdue=true`: add `Todo.due_date.is_not(None)`, `Todo.due_date < now`, `Todo.done.is_(False)`.
   - `overdue=false`: add `or_(Todo.due_date.is_(None), Todo.due_date >= now, Todo.done.is_(True))`.
   - Keep the existing `done` filter as a separate AND clause so `?done=false&overdue=true` composes. (`?done=true&overdue=true` legitimately returns an empty list; do not special-case it.)
   - Binding `now` through the `UTCDateTime` column type keeps the literal in the same string format SQLite stores, so the `<` comparison is correct. Do not compare against a hand-formatted string.

### 4. `alembic/versions/0002_add_due_date.py` — migration
1. Generate with `alembic revision -m "add due_date to todos"`; set `down_revision` to the 0001 revision id.
2. `upgrade`: `op.add_column("todos", sa.Column("due_date", sa.DateTime(), nullable=True))`. Use plain `sa.DateTime` here, not the decorator; the migration should not import app code.
3. `downgrade`: drop the column inside `op.batch_alter_table("todos")` so it works on SQLite versions without native `DROP COLUMN`.
4. Verify on a copy of `todo.db`: `alembic upgrade head`, confirm the column with `sqlite3 ... ".schema todos"`, then `alembic downgrade -1` and `upgrade head` again.
5. Because the test suite builds tables from the models, nothing in CI proves the migration matches the model. Manually diff the migration column against the model column (name, type, nullable), and mention in the PR that the migration was run by hand.

### 5. `tests/test_todos.py` — new cases
Add these tests (names are suggestions; use the file's existing conventions):
1. `test_create_without_due_date` — POST with no `due_date`; response has `"due_date": null`.
2. `test_create_with_due_date` — POST with an aware ISO string; response echoes it in UTC.
3. `test_create_due_date_with_offset_is_normalized_to_utc` — send `...T10:00:00+02:00`; response shows `...T08:00:00Z` (or `+00:00`, whichever the serializer emits; assert by parsing, not string equality).
4. `test_create_naive_due_date_is_treated_as_utc` — send `...T10:00:00`; response shows 10:00 UTC.
5. `test_create_invalid_due_date_returns_422`.
6. `test_patch_sets_due_date` — PATCH with a value on a todo that had none.
7. `test_patch_clears_due_date` — PATCH with `"due_date": null`; response has null.
8. `test_patch_without_due_date_leaves_it_unchanged` — PATCH only `title`; `due_date` preserved.
9. `test_overdue_includes_past_and_not_done`.
10. `test_overdue_excludes_done` — past due date, `done: true`.
11. `test_overdue_excludes_future`.
12. `test_overdue_excludes_null_due_date`.
13. `test_overdue_combines_with_done_filter` — `?done=false&overdue=true` returns only the past-and-not-done item; `?done=true&overdue=true` returns `[]`.
14. `test_overdue_false_returns_complement` (only if the default in section 0 is kept).
Practical notes:
- Use dates far in the past/future (e.g. 2000-01-01, 2100-01-01) rather than patching the clock; the handler computes `now` internally.
- The existing twelve tests may assert on exact response dicts. Those will now include `"due_date": None`; update them rather than loosening assertions.
- No changes to the in-memory DB fixture are needed; `Base.metadata.create_all` picks up the new column automatically.
