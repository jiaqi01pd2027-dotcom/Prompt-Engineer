Feature: optional `due_at` on each todo, plus an `overdue` filter on GET /todos (overdue = due_at in the past and done is false).

Decision up front: store the due date as a UTC datetime named `due_at` (nullable), not a bare date, so it matches `created_at` and so "in the past" has a single unambiguous meaning. Overdue is computed at query time, never stored.

1. app/models.py: add `due_at` DateTime column, nullable, no default. Store it the same way `created_at` is stored (naive UTC or timezone-aware, whichever the existing column uses) so the two columns compare consistently.
2. alembic/versions/0002_add_due_at.py: add the nullable column. No server default and no backfill; existing rows stay null, which means "no due date". Down-revision points at 0001.
3. app/schemas.py: add `due_at: datetime | None` to TodoCreate (optional, default None), TodoUpdate (optional) and TodoOut. Add a validator that normalizes any incoming value to UTC (convert aware datetimes, treat naive ones as UTC) so what reaches the model always matches the storage convention. Do not reject past dates on create or patch; a user may legitimately record something already overdue.
4. app/routes.py:
   - PATCH /todos/{id}: the update must distinguish "field not sent" from "sent as null", because null is how a client clears the due date. Build the update from `model_dump(exclude_unset=True)` (check how the existing patch handles `title`/`done` and keep the same approach) so `{"due_at": null}` clears the column and omitting it leaves it alone.
   - GET /todos: add optional query param `overdue: bool | None`. Compute `now` once in UTC at the start of the handler. When `overdue=true`, filter `due_at IS NOT NULL AND due_at < now AND done = false`. When `overdue=false`, filter the complement (`due_at IS NULL OR due_at >= now OR done = true`). Combine with the existing `done` filter using AND; `overdue=true&done=true` is contradictory and simply returns an empty list, no special-casing.
   - POST /todos: pass the field through, no other changes.
5. app/db.py: no changes.
6. tests/test_todos.py: create without due date returns `due_at: null`; create with due date round-trips as ISO 8601 UTC; invalid due date string returns 422; patch sets a due date; patch with `{"due_at": null}` clears it; patch that omits `due_at` leaves it untouched. For the filter, seed four todos: past due and not done, past due and done, future due and not done, no due date; assert `overdue=true` returns only the first, `overdue=false` returns the other three, and `overdue=true&done=true` returns empty. Use due dates far in the past and future (days, not seconds) so no clock freezing is needed. Tests build tables from models, so the model change alone makes them pass; check the migration by running `alembic upgrade head` against a copy of todo.db locally and confirming existing rows read back with `due_at` null.

Risks:
- Mixed aware and naive datetimes. SQLite has no real datetime type; SQLAlchemy stores strings and compares them lexically, and `DateTime(timezone=True)` silently drops tzinfo on SQLite. If `due_at` is stored aware and `now` is naive (or vice versa), the comparison is wrong or raises. Normalize in the schema validator and construct `now` the same way `created_at` is generated.
- Patch semantics. If the update uses `model_dump()` without `exclude_unset=True`, every PATCH will wipe `due_at` back to null. The "omit leaves it alone" test exists to catch this.
- Timezone of the response. TodoOut should serialize `due_at` with an explicit UTC offset (`Z`) so clients do not interpret it as local time; check what `created_at` does today and match it.
- `overdue` is evaluated against server time at request time, so a todo can flip from not-overdue to overdue between two calls with no writes. This is expected; document it in the route docstring so nobody files it as a bug.
