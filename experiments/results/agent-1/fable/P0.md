The repo isn't in any of the working directories, so this is based on your description. Here's how I'd do it, in the order that keeps the tests green at each step.

## 1. Model — `app/models.py`

Add one nullable column. Nullable is the right call: existing rows have no due date, and most todos won't need one.

```python
due_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
```

Match whatever style `created_at` uses (naive vs. timezone-aware). If `created_at` is a naive UTC datetime, keep `due_at` naive UTC too — mixing aware and naive datetimes in SQLite comparisons is a classic source of silent bugs.

## 2. Migration — `alembic/versions/0002_add_due_at.py`

```python
def upgrade():
    op.add_column("todos", sa.Column("due_at", sa.DateTime(timezone=True), nullable=True))

def downgrade():
    op.drop_column("todos", column_name="due_at")
```

SQLite handles `add_column` for a nullable column without a table rebuild, so no `batch_alter_table` needed. Set `down_revision` to `0001`'s revision id.

Since the tests build tables from the models rather than running migrations, the tests won't catch a model/migration mismatch. Run `alembic upgrade head` against a scratch copy of `todo.db` once to confirm.

## 3. Schemas — `app/schemas.py`

- `TodoCreate`: add `due_at: datetime | None = None`
- `TodoUpdate`: add `due_at: datetime | None = None`
- `TodoOut`: add `due_at: datetime | None`

One wrinkle on `TodoUpdate`: with `None` as the default you can't distinguish "not sent" from "clear the due date". If you want PATCH to be able to *remove* a due date, build the update dict with `model_dump(exclude_unset=True)` in the route (you may already be doing this for `title`/`done`) — then an explicit `"due_at": null` in the body clears it, while omitting the field leaves it alone.

## 4. Routes — `app/routes.py`

If POST and PATCH already do `Todo(**payload.model_dump())` / `setattr` loops over `model_dump(exclude_unset=True)`, they pick up `due_at` with no changes. Check that PATCH isn't enumerating fields by name.

Optional but useful: extend `GET /todos` filtering alongside the existing `done` param:

```python
due_before: datetime | None = None,
overdue: bool | None = None,
```

`overdue=true` → `due_at < now() AND done = false`. Also consider `ORDER BY due_at ASC NULLS LAST` so dated todos sort first.

## 5. Tests — `tests/test_todos.py`

Add roughly five tests:

- create with `due_at` → response echoes it back in ISO format
- create without `due_at` → `null`
- patch sets a due date on an existing todo
- patch with `"due_at": null` clears it (this is the one that catches the exclude_unset issue)
- list with `overdue=true` returns only past-due, not-done todos (if you add the filter)

Watch for the timezone round-trip: Pydantic will serialize an aware datetime as `...+00:00` or `Z` depending on version, so compare parsed datetimes rather than raw strings.

## Suggested order

Model → schemas → run tests (should still be green; new field is optional) → routes → new tests → migration last, verified against a real db file. The migration is the only step the test suite can't cover for you.
