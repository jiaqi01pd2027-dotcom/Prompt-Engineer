Risks:
- Model and migration drift, because CI builds tables from models and never executes the migration: run `alembic upgrade head` and `downgrade -1` against a copy of production `todo.db` before merging (step 1), and have the reviewer diff the column definition in `0002` against the one in `models.py` line by line (type `DateTime`, nullable, no default).
- Deploying app code before the migration runs would make every SELECT on `todos` fail with "no such column: due_date", taking the API down: confirm the deploy pipeline runs `alembic upgrade head` before restarting the app process (it is the documented order); because the column is nullable with no default, the migration is also safe to run before the old code is stopped, so run it first.
- SQLite compares datetimes as strings, so any value written in a different format (tz-aware, different precision) silently breaks the `<` comparison and the overdue filter returns wrong results without erroring: normalize in exactly one place (the schema validator in step 3) so nothing tz-aware ever reaches the model, compare against a naive UTC Python datetime rather than SQL `now()`, and keep `test_create_todo_with_offset_due_date_is_normalized_to_utc` plus `test_list_overdue_returns_only_past_due_and_not_done` as the guards.
- Rejecting naive timestamps with 422 may surprise a client that currently sends local times without an offset: the agreed contract is ISO-8601 with offset, so keep the strict behaviour, make the 422 message state explicitly that an offset is required, and tell the web and mobile teams before release so they can verify their serializers emit offsets.
- Tests that compare "past" against the real clock become flaky near boundaries or on machines with skewed clocks: use the fixed PAST (year 2000) and FUTURE (year 2100) constants for every overdue test and never compute `now()` inside a test.
- Downgrade on SQLite fails with a plain `op.drop_column`: use `batch_alter_table` in `downgrade()` and exercise the downgrade once on the local DB copy as part of step 1.
