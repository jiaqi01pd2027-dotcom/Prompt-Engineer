Tests:
- POST /todos without `due_date` returns 201 with `due_date: null`.
- POST /todos with an ISO 8601 `due_date` returns it unchanged (normalized to UTC) in the response.
- POST /todos with a malformed `due_date` string returns 422.
- POST /todos with a naive datetime is either normalized to UTC or rejected, per the choice in step 3.
- GET /todos/{id} includes `due_date` for a todo that has one.
- PATCH /todos/{id} with `due_date` sets it; PATCH with only `title` leaves an existing `due_date` untouched.
- PATCH /todos/{id} with `due_date: null` clears an existing due date.
- GET /todos?overdue=true returns a todo whose due date is in the past and `done` is false.
- GET /todos?overdue=true excludes a todo whose due date is in the past but `done` is true.
- GET /todos?overdue=true excludes a todo whose due date is in the future.
- GET /todos?overdue=true excludes a todo with no due date.
- GET /todos?overdue=false returns exactly the complement: no-due-date, future-due, and done-past-due todos.
- GET /todos?overdue=true&done=true returns an empty list; GET /todos?overdue=true&done=false matches overdue=true alone.
- GET /todos with no `overdue` param returns all todos regardless of due date (existing list tests still pass).
- Boundary: a todo whose due date equals the mocked "now" is not overdue (strict less-than).
- All twelve existing tests still pass unchanged.

Risks:
- Naive vs aware datetime comparison raises TypeError or silently compares wrong in SQLite: normalize every input to aware UTC in the schema validator and always compare against an aware `utcnow()`; SQLite stores datetimes as strings, so keep one consistent format.
- Tests bypass Alembic, so the model and migration can drift without any test failing: run `alembic upgrade head` against a scratch file DB once during review and compare `PRAGMA table_info(todos)` to the model, or add a one-off test that runs the migration and checks the column exists.
- Time-dependent tests are flaky around midnight or under slow CI: monkeypatch the `utcnow()` helper rather than using `datetime.now()` directly in tests.
- PATCH cannot distinguish "not sent" from "sent as null" without `exclude_unset`: use `model_dump(exclude_unset=True)` and add an explicit test for clearing.
- SQLite `ALTER TABLE DROP COLUMN` fails on older SQLite builds during downgrade: use Alembic batch mode in `downgrade`, and note that downgrade is best-effort.
- `overdue=true` combined with `done=true` is contradictory and could confuse API consumers: document that filters AND together and return an empty list rather than a 400, so clients can compose filters mechanically.
- Existing production rows get `due_date = NULL` after migration, which the `overdue=false` filter must treat as not overdue: the `IS NULL` clause in step 7 covers this; test it explicitly.
- Query params in FastAPI parse `overdue=1`/`yes` as booleans but arbitrary strings as 422: acceptable, but call it out in the docs.
