# Implementation Plan: Optional Due Date + `overdue` Filter

**Feature:** add an optional `due_date` field to each todo, plus an `overdue` query filter on `GET /todos` (due date is in the past and `done` is false).

1. **app/models.py**: add `due_date` column — `DateTime`, nullable, no default, no server default. Store as UTC (consistent with `created_at`). No backfill needed since existing rows simply have `NULL`.

2. **alembic/versions/0003_add_due_date.py**: add the nullable `due_date` column to `todos`. No server default and no data migration required — nullable column, existing rows land as `NULL` automatically.

3. **app/schemas.py**:
   - `TodoCreate`: add `due_date: Optional[datetime] = None`.
   - `TodoUpdate`: add `due_date: Optional[datetime] = None`; decide and document how PATCH distinguishes "field omitted" from "explicitly clear the due date" — use `exclude_unset` in the route handler so omitting the field leaves it untouched, while sending `"due_date": null` clears it.
   - `TodoOut`: add `due_date: Optional[datetime]`.

4. **app/routes.py**:
   - `POST /todos`: pass `due_date` through from `TodoCreate` unchanged.
   - `PATCH /todos/{id}`: apply `due_date` via `exclude_unset` semantics as above.
   - `GET /todos`: add optional query param `overdue: bool`. When `overdue=true`, filter to rows where `due_date IS NOT NULL AND due_date < <current UTC time> AND done = false`. Combine with the existing `done` query param using AND (same pattern as the existing filter) — note explicitly that passing `overdue=true&done=true` together is a contradiction and will always return an empty list; that's acceptable, don't special-case it.
   - Compute "now" once per request in the route (e.g., `datetime.utcnow()`) rather than relying on a DB-side `now()` function, to keep behavior identical between the SQLite test DB and production.

5. **tests/test_todos.py**:
   - Create a todo without a due date; confirm `due_date` is `None` in the response.
   - Create a todo with a due date; confirm it round-trips through `GET /todos/{id}`.
   - PATCH to set a due date on a todo that had none.
   - PATCH with `due_date: null` to clear an existing due date; PATCH with `due_date` omitted to confirm it's left untouched.
   - `GET /todos?overdue=true` returns a todo with a past due date and `done=false`.
   - Same filter excludes: a todo with a future due date, a todo with no due date, and a todo with a past due date but `done=true`.
   - `overdue=true` combined with `done=false` still returns the overdue todo; combined with `done=true` returns empty.
   - Note: since tests build tables from models directly (no migrations run), the model change alone makes these pass; verify the migration separately with `alembic upgrade head` locally.

**Risks / decisions to flag to the developer:**
- **Tri-state PATCH**: Pydantic can't tell "field omitted" from "field set to null" unless the handler uses `exclude_unset` (or a sentinel). Decide this before writing `TodoUpdate`/the PATCH handler — the plan above assumes `exclude_unset`, but confirm it matches how `TodoUpdate` already handles optional `title`/`done` today, for consistency.
- **Time zone / "now" comparison**: `created_at` is already stored as UTC; `due_date` must follow the same convention, and the "now" used for the overdue comparison must be UTC too, or overdue results will be off by the server's local offset. Compute "now" in Python once per request rather than trusting SQLite's own datetime functions, since behavior there can differ from the production DB.
- **Empty/contradictory filter combos**: `overdue=true&done=true` is contradictory and yields an empty list by design — document this rather than adding special-case logic.
