## 1. `app/models.py` — add the column

```python
from datetime import date

due_date: Mapped[date | None] = mapped_column(Date, nullable=True)
```

Nullable so existing todos (and new ones) don't require a due date. Use `Date` rather than `DateTime` unless you actually need time-of-day — simpler for "due dates."

## 2. `app/schemas.py` — expose it

- `TodoCreate`: add `due_date: date | None = None`
- `TodoUpdate`: add `due_date: date | None = None` (already optional-fields style, so this fits the existing pattern)
- `TodoOut`: add `due_date: date | None`

## 3. `alembic/versions/` — new migration

Create `0002_add_due_date.py` (revision chained after `0001_create_todos`):

```python
def upgrade():
    op.add_column("todos", sa.Column("due_date", sa.Date(), nullable=True))

def downgrade():
    op.drop_column("todos", "due_date")
```

Nullable + no default means this is a safe additive migration — no backfill needed, no lock issues on SQLite.

## 4. `app/routes.py` — wire it through

- POST `/todos`: pass `due_date` through when constructing the model (falls out naturally once it's in `TodoCreate`).
- PATCH `/todos/{id}`: same — if the update path does `for field, value in update.dict(exclude_unset=True).items(): setattr(todo, field, value)` or similar, `due_date` is already covered. If instead each field is set explicitly, add `if update.due_date is not None: todo.due_date = update.due_date` (or handle explicit clearing — see below).
- GET `/todos`: consider adding an optional `overdue: bool` or `due_before`/`due_after` query param if you want filtering, mirroring the existing `done` filter pattern. Not required, but likely wanted alongside due dates.

One decision to make explicitly: **can a due date be cleared once set?** With Pydantic's `exclude_unset=True` pattern, sending `{"due_date": null}` in a PATCH clears it, while omitting the field leaves it untouched — that's the standard way to support both "don't touch" and "clear" semantics. If the update logic instead treats `None` as "no change," clearing becomes impossible — worth checking which the current `TodoUpdate` handling does for `done`/`title` and mirroring it.
