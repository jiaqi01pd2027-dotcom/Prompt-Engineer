Two real bugs; the third function was already correct.

**1. `tag_records` — mutable default argument.** `tags=[]` is created once at function-definition time, so `"processed"` accumulates across calls. The original prints `['processed']` then `['processed', 'processed']`. It also mutated any list the caller passed in. Fix: default to `None` and build a local copy.

**2. `moving_average` — off-by-one.** `range(len(values) - window)` drops the final window. For `[1, 2, 3, 4]` with `window=2` it returned `[1.5, 2.5]` instead of `[1.5, 2.5, 3.5]`; with `window == len(values)` it returned `[]`. Fix: `range(len(values) - window + 1)`. I also added a guard for `window <= 0`, which otherwise silently returns a wrong-length result.

**3. `number_lines` — no bug.** `enumerate(lines, start=1)` already produces `['1: alpha', '2: beta']`, matching the docstring.

```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    tags = list(tags) if tags else []
    tags.append("processed")
    return [dict(record, tags=list(tags)) for record in records]


def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    if window <= 0:
        raise ValueError("window must be positive")
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages


def number_lines(lines):
    """Prefix each line with its 1-based line number, e.g. '1: first'."""
    return [f"{index}: {line}" for index, line in enumerate(lines, start=1)]
```
