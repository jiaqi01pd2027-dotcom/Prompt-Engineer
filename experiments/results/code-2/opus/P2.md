## Bug 1 — `tag_records`: mutable default argument

`tags=[]` is evaluated once, at function definition time, so every call that omits `tags` shares the same list object. `tags.append("processed")` mutates that shared list, so the marker accumulates across calls. Running the original proves it:

```
[{'id': 1, 'tags': ['processed']}]
[{'id': 2, 'tags': ['processed', 'processed']}]    # <-- leaked from the previous call
```

A third call would produce three copies, and so on. The same `append` also mutates a caller-supplied list as a side effect, which the docstring does not advertise.

```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    tags = list(tags) if tags is not None else []
    tags.append("processed")
    return [dict(record, tags=list(tags)) for record in records]
```

`None` as the sentinel gives a fresh list per call; copying with `list(tags)` keeps the caller's list unmodified. The inner `list(tags)` in the comprehension stays — it is what stops every record from sharing one tag list.

## Bug 2 — `moving_average`: off-by-one in the range

A sequence of length `n` contains `n - window + 1` windows of size `window`, not `n - window`. The loop drops the final window. `moving_average([1, 2, 3, 4], 2)` returns `[1.5, 2.5]` and silently loses `3.5`; with `window == len(values)` it returns `[]` instead of the single average.

```python
def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages
```

After the fix: `[1, 2, 3, 4]` with `window=2` gives `[1.5, 2.5, 3.5]`, with `window=4` gives `[2.5]`, and an oversized window still yields `[]` because the range is empty — no new edge case introduced.
