Both bugs confirmed by running the code, and both fixes verified.

## Bug 1 — `tag_records`: mutable default argument

`tags=[]` is evaluated once, when the function is defined, so every call that omits `tags` shares the *same* list. `tags.append("processed")` then mutates that shared list permanently. The original output proves it:

```
[{'id': 1, 'tags': ['processed']}]
[{'id': 2, 'tags': ['processed', 'processed']}]   # leaked from the previous call
```

The same append also mutates a caller-supplied list as a side effect.

```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    tags = list(tags) if tags is not None else []
    tags.append("processed")
    return [dict(record, tags=list(tags)) for record in records]
```

`None` as the sentinel gives a fresh list per call; copying with `list(tags)` keeps the caller's list untouched.

## Bug 2 — `moving_average`: off-by-one in the loop range

For a window of size `window`, there are `len(values) - window + 1` valid starting positions. `range(len(values) - window)` stops one short and silently drops the final window: `moving_average([1, 2, 3, 4], 2)` returned `[1.5, 2.5]` instead of `[1.5, 2.5, 3.5]`. With `window == len(values)` it returns `[]` rather than the single average.

```python
def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages
```

## Not a bug — `number_lines`

`enumerate(lines, start=1)` already produces 1-based numbering: `['1: alpha', '2: beta']`, exactly as the docstring specifies. Left unchanged.

After the fixes: `tag_records` gives `['processed']` on both calls, a caller list `['a']` comes back unmutated, `moving_average([1,2,3,4], 2)` → `[1.5, 2.5, 3.5]`, and `moving_average([1,2,3,4], 4)` → `[2.5]`.
