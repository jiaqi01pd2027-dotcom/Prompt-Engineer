## Bugs found

**Bug 1 — `tag_records`: mutable default argument reused across calls**

`tags=[]` is created **once**, when the function is defined, not per call. Because the body does `tags.append("processed")` — mutating that shared default in place — every subsequent call that relies on the default keeps appending to the *same* list. That's exactly the reported symptom: the first call in a batch gets `["processed"]`, but each later call in the same run accumulates more copies (`["processed", "processed"]`, `["processed", "processed", "processed"]`, ...).

Demonstration with the given `__main__` block:
```
tag_records([{"id": 1}])  -> tags == ["processed"]
tag_records([{"id": 2}])  -> tags == ["processed", "processed"]   # bug
```

Fix — use `None` as the sentinel default and build a fresh list every call (this also avoids the secondary problem of mutating a caller-supplied list in place):

```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    if tags is None:
        tags = []
    tags = tags + ["processed"]
    return [dict(record, tags=list(tags)) for record in records]
```

**Bug 2 — `moving_average`: off-by-one in the loop range**

`range(len(values) - window)` excludes the final valid starting position. For a window of size `window` over a list of length `n`, valid start indices are `0 .. n - window` *inclusive*, i.e. `n - window + 1` positions — not `n - window`.

With `values=[1,2,3,4]`, `window=2`: `n - window = 2`, so `range(2)` only yields starts `0, 1`, producing chunks `[1,2]` and `[2,3]` → 2 averages. The valid start `2` (chunk `[3,4]`) is silently dropped, matching the reported "only two values, expected three" bug.

Fix — add 1 so the last valid start is included:

```python
def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages
```

## Not a bug

`number_lines` is correct as written: `enumerate(lines, start=1)` numbers from 1, matching how editors/diff viewers display line numbers. No change needed there.

## Full corrected module

```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    if tags is None:
        tags = []
    tags = tags + ["processed"]
    return [dict(record, tags=list(tags)) for record in records]


def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages


def number_lines(lines):
    """Prefix each line with its 1-based line number, e.g. '1: first'."""
    return [f"{index}: {line}" for index, line in enumerate(lines, start=1)]


if __name__ == "__main__":
    print(tag_records([{"id": 1}]))
    print(tag_records([{"id": 2}]))
    print(moving_average([1, 2, 3, 4], 2))
    print(number_lines(["alpha", "beta"]))
```

Expected output now: each `tag_records` call yields `tags: ['processed']` independently; `moving_average` returns `[1.5, 2.5, 3.5]` (three values); `number_lines` is unchanged (`['1: alpha', '2: beta']`).
