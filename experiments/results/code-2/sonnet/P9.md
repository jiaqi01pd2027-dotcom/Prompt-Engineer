## Bugs found (exactly two, as expected)

**1. `tag_records`: mutable default argument**

```python
def tag_records(records, tags=[]):
```

The default list `[]` is created **once**, when the function is defined, and reused across every call that doesn't pass `tags` explicitly. Since the body does `tags.append("processed")`, each call permanently mutates that shared default list. First call appends one `"processed"`, second call appends another on top of the leftover one, etc. — exactly the "later records come back with several `processed` entries" symptom you described.

Fix: use `None` as the sentinel default and build a fresh list inside the function.

**2. `moving_average`: off-by-one in the loop range**

```python
for start in range(len(values) - window):
```

This produces `len(values) - window` slices instead of `len(values) - window + 1`. For `[1, 2, 3, 4]` with `window=2`, `len(values) - window == 2`, so `start` only takes values `0, 1`, giving chunks `[1,2]` and `[2,3]` (averages `1.5, 2.5`) — the final valid chunk `[3,4]` (average `3.5`) is dropped.

Fix: `range(len(values) - window + 1)`.

`number_lines` was left untouched per your answer — it's intentional 1-based numbering.

## Corrected snippet

```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    if tags is None:
        tags = []
    tags = tags + ["processed"]
    return [dict(record, tags=list(tags)) for record in records]


def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages


def number_lines(lines):
    """Prefix each line with its 1-based line number, e.g. '1: first'."""
    return [f"{index}: {line}" for index, line in enumerate(lines, start=1)]


if __name__ == "__main__":
    print(tag_records([{"id": 1}]))
    print(tag_records([{"id": 2}]))
    print(moving_average([1, 2, 3, 4], 2))
    print(number_lines(["alpha", "beta"]))
```

Note on the `tag_records` fix: I used `tags = tags + ["processed"]` (creates a new list) rather than mutating the caller-supplied list in place with `.append`. This also protects against a second latent issue — if a caller *does* pass their own list explicitly and reuses it across calls, the old code would keep appending `"processed"` to their list too. Since you only mentioned two bugs and this is really the same root cause (accidental shared/mutated state), I folded it into fix #1 rather than counting it separately.
