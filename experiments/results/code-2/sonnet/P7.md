## Reasoning trace

**`tag_records`** — called twice with fresh single-item lists and no `tags` argument.
- Call 1: `tags` binds to the default list object (empty). `tags.append("processed")` mutates that *same* default object to `["processed"]`. Returns `[{"id": 1, "tags": ["processed"]}]` — looks fine.
- Call 2: Python reuses the *same* default list object (defaults are evaluated once, at function-definition time). It's now `["processed"]` from the previous call. Appending again gives `["processed", "processed"]`. Returns `[{"id": 2, "tags": ["processed", "processed"]}]`.

The docstring promises "tags plus a 'processed' marker" for every call — it doesn't say the marker should pile up across unrelated calls. Second call's output is wrong. This is the classic **mutable default argument** bug, confirmed.

**`moving_average([1, 2, 3, 4], 2)`** — docstring: "average of every consecutive window-sized slice."
- `range(len(values) - window)` = `range(4 - 2)` = `range(2)` → `start` takes 0, 1.
  - start=0: `[1,2]` → 1.5
  - start=1: `[2,3]` → 2.5
- The slice starting at `start=2`, i.e. `[3,4]` → 3.5, is a valid consecutive window-sized slice but is never produced. Result is `[1.5, 2.5]` instead of `[1.5, 2.5, 3.5]`. Off-by-one, confirmed bug — should be `range(len(values) - window + 1)`.

**`number_lines(["alpha", "beta"])`** — `enumerate(lines, start=1)` gives `(1, "alpha"), (2, "beta")` → `["1: alpha", "2: beta"]`, exactly matching the docstring's example format. No bug here; left unchanged.

## Findings:

**Bug 1 — `tag_records`: mutable default argument**

`tags=[]` as a default is created once at function-definition time and reused across all calls that don't pass `tags` explicitly. `tags.append("processed")` mutates that shared list in place, so the second (and every subsequent) call accumulates extra `"processed"` entries instead of starting fresh.

Fix:
```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    if tags is None:
        tags = []
    tags = tags + ["processed"]
    return [dict(record, tags=list(tags)) for record in records]
```
(Using `tags + [...]` instead of `tags.append(...)` also avoids mutating a caller-supplied list, which is the safer general fix for this pattern.)

**Bug 2 — `moving_average`: off-by-one in the loop range**

`range(len(values) - window)` excludes the final valid window start position. For a list of length `n` and window size `w`, valid start indices are `0 .. n - w` inclusive, i.e. `range(n - w + 1)`. As written, the last window is silently dropped.

Fix:
```python
def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages
```

`number_lines` has no bug and was left unchanged.
