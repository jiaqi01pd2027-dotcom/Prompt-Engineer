Confirmed both bugs by running the code. Here are the findings:

**Function: `tag_records`**
Problem: `tags=[]` is a mutable default argument. That same list object persists across calls, and `tags.append("processed")` mutates it in place — so tags from earlier calls leak into later ones. Running it twice shows the bug: the second call returns `tags: ['processed', 'processed']` instead of `['processed']`.

Fix:
```python
def tag_records(records, tags=None):
    """Attach `tags` plus a 'processed' marker to every record."""
    tags = (tags or []) + ["processed"]  # fresh list each call; doesn't mutate caller's list either
    return [dict(record, tags=list(tags)) for record in records]
```

**Function: `moving_average`**
Problem: `range(len(values) - window)` stops one short — it should stop at the last valid start index, which is `len(values) - window` *inclusive*. For `values=[1,2,3,4], window=2`, valid starts are 0, 1, 2 (chunks `[1,2]`, `[2,3]`, `[3,4]`), but `range(4-2)` = `range(2)` only yields 0, 1, silently dropping the final chunk `[3,4]`. Confirmed: the function returns `[1.5, 2.5]` instead of `[1.5, 2.5, 3.5]`.

Fix:
```python
def moving_average(values, window):
    """Return the average of every consecutive `window`-sized slice."""
    averages = []
    for start in range(len(values) - window + 1):
        chunk = values[start:start + window]
        averages.append(sum(chunk) / window)
    return averages
```

`number_lines` is correct as written and was left unchanged — `enumerate(lines, start=1)` correctly produces 1-based numbering for every line.
