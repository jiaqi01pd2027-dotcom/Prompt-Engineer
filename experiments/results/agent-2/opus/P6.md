Usage Dashboard — implementation plan

**Scope (in):** a usage page in the existing web app showing an account's current billing-period total for the metered unit we bill on, a daily time series for the last 30 days, and a breakdown by top dimension (project or API key), refreshed at least hourly.

**Non-goals:** real-time or sub-minute numbers, per-seat/per-user analytics, CSV export, usage alerts or thresholds, cost and invoice projections, history beyond 13 months, a public usage API, admin-side cross-account views.

**Assumptions and open questions:** (assumption) metering events are already recorded for billing and can be rolled up into a summary table, so no new instrumentation; (question) is the billed unit the one customers actually want to see, or are they asking about something else — requests, storage, seats? (question) must the dashboard reconcile exactly with the invoice, or is "approximate, as of an hour ago" acceptable? (question) how far back does usable event history actually go, and is it consistent across the retention change?

**Milestones:** 1. rollup job and backfill of historical events, 1.5 weeks. 2. read API with account scoping and caching, 1 week. 3. chart, breakdown, and empty/loading/error states, 1 week. 4. reconcile a month of accounts against invoices, add instrumentation, release behind a flag, 1 week.

**Risks:** dashboard numbers disagree with the invoice and generate support tickets — reconcile against real invoices in milestone 4, stamp the page with an "as of" time, and state that billing is authoritative. Backfill scans the raw events table and degrades production — chunk it and run off-peak. Largest accounts have thousands of dimensions and blow up the breakdown query — pre-aggregate to top N plus "other". A wrong join leaks one account's usage into another's rollup — account id in the rollup primary key, plus a cross-account test before milestone 2 ships.

Two things worth settling before milestone 1 starts: which metric, and whether it has to match the invoice. Both change the shape of the rollup, and both are cheap to answer now and expensive to change after the backfill runs.
