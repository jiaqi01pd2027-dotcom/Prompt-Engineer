Here is the function, tested against the examples in the spec plus a set of invalid inputs.

```python
import re

_SECONDS_PER = {
    "years": 365 * 86400,
    "months": 30 * 86400,
    "weeks": 7 * 86400,
    "days": 86400,
    "hours": 3600,
    "minutes": 60,
}

# Weeks form: "PnW" and nothing else (weeks never combine with other designators).
_WEEKS_RE = re.compile(r"^P(?P<weeks>\d+)W$")

# General form. Each component is optional, but:
#   - "P" alone is rejected by the (?!$) lookahead
#   - "T" must be followed by at least one time component (the (?=\d) lookahead)
#   - only the seconds component may carry a fraction ("." or "," per ISO 8601)
_GENERAL_RE = re.compile(
    r"^P(?!$)"
    r"(?:(?P<years>\d+)Y)?"
    r"(?:(?P<months>\d+)M)?"
    r"(?:(?P<days>\d+)D)?"
    r"(?:T(?=\d)"
    r"(?:(?P<hours>\d+)H)?"
    r"(?:(?P<minutes>\d+)M)?"
    r"(?:(?P<seconds>\d+(?:[.,]\d+)?)S)?"
    r")?$"
)


def parse_iso_duration(s: str) -> "float | int":
    """Convert an ISO-8601 duration string to a total number of seconds.

    Uses fixed unit lengths: 1 year = 365 days, 1 month = 30 days,
    1 week = 7 days, 1 day = 24 hours. Returns an int when the duration has
    no fractional seconds, otherwise a float.

    Raises ValueError for anything that is not a valid ISO-8601 duration.
    """
    if not isinstance(s, str):
        raise ValueError(f"ISO-8601 duration must be a string, got {type(s).__name__}")

    m = _WEEKS_RE.match(s)
    if m:
        return int(m.group("weeks")) * _SECONDS_PER["weeks"]

    m = _GENERAL_RE.match(s)
    if not m:
        raise ValueError(f"Invalid ISO-8601 duration: {s!r}")

    total = 0
    for unit, factor in _SECONDS_PER.items():
        value = m.group(unit) if unit != "weeks" else None
        if value is not None:
            total += int(value) * factor

    seconds = m.group("seconds")
    if seconds is not None:
        seconds = seconds.replace(",", ".")
        if "." in seconds:
            return total + float(seconds)
        total += int(seconds)

    return total
```

**How it works**

- Two anchored regexes do all validation. The weeks form (`P2W`) is matched first and is exclusive, so `P1W2D` or `P2WT1H` fail. The general form fixes the component order (Y, M, D, then `T`, H, M, S), which is how the regex distinguishes months-`M` from minutes-`M`.
- `^P(?!$)` rejects a bare `"P"`; `T(?=\d)` rejects a dangling `"PT"` or `"P1DT"`; a time unit without `T` (`"P1H"`, `"P1S"`) simply has no branch to match. Fractions are only permitted in the seconds group, so `"P1.5D"` and `"PT1.5H"` raise.
- Return type: `int` when there is no fractional seconds part (e.g. `PT36H` -> `129600`), `float` when there is (`PT1.5S` -> `1.5`), so integer intervals stay exact.

**Behavior notes**

- Strict about case and whitespace: `"p1d"` and `" P1D"` raise. ISO 8601 designators are uppercase, and for a billing pipeline I'd rather reject than normalize; call `.strip().upper()` before parsing if you want leniency.
- Accepts a comma as the decimal mark in seconds (`PT1,5S`), which ISO 8601 permits. Easy to remove from the regex if you want dot-only.
- Negative durations, signs, and the alternative `P0001-02-03T04:05:06` format are rejected.
- Non-string input raises `ValueError` rather than a `TypeError`, per the "fail loudly with ValueError" requirement.

Verified against: all five spec examples, `PT0S`, `P0D`, `P1YT1S`, and 27 invalid strings including `""`, `"P"`, `"PT"`, `"1D"`, `"P1H"`, `"PT1D"`, `"P1.5D"`, `"PT.5S"`, `"PT1.S"`, `"P-1D"`, `"P1X"`, `"PT1S1H"` (out-of-order), `"P1YY"`, and `"PT1.5.5S"`. All pass.
