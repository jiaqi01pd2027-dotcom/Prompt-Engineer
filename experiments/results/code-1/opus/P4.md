```python
import re

_DURATION_RE = re.compile(
    r"""
    P
    (?:
        (?P<weeks>\d+)W
      |
        (?P<date>(?:(?P<years>\d+)Y)?(?:(?P<months>\d+)M)?(?:(?P<days>\d+)D)?)
        (?:T(?P<time>
            (?:(?P<hours>\d+)H)?
            (?:(?P<minutes>\d+)M)?
            (?:(?P<seconds>\d+)(?:\.(?P<fraction>\d+))?S)?
        ))?
    )
    """,
    re.VERBOSE | re.ASCII,
)
```

Design notes:

- One regex with two alternatives: the standalone week form `PnW`, or the ordered date/time form. Ordering, repetition, and unknown characters are rejected structurally by `fullmatch`, so no post-hoc character scanning.
- `P`, `PT`, and `P1DT` all match the pattern (every component is optional), so they are rejected explicitly after the match via the `date`/`time` group emptiness checks.
- Fractions are only reachable inside the seconds group, so `P1.5D`, `PT1.5H`, `P1.5W` all fail. Comma as decimal separator is rejected too, matching your spec's literal wording ("fractional seconds like PT1.5S").
- Return type: `int` for whole-second durations, `float` only when a fraction is present. The fractional part is added last as `float("0." + digits)` so the integer part keeps full precision.
- Non-string input raises `ValueError` (not `TypeError`), per your "raise ValueError specifically" constraint.
- `from __future__ import annotations` keeps the `float | int` annotation valid on the local Python 3.9; without it that signature raises at import time on <3.10.
