**Design**

A single `re.VERBOSE` pattern with named groups is the whole validator — one alternation between the standalone week form (`P2W`) and the date/time form, so `P1W2D` and `P1WT1H` are rejected structurally rather than by a follow-up check. Ordering is enforced by construction, so `PT5M3H` and `P3D2M` fail. The fraction `\d+(?:\.\d+)?` lives only on the seconds group, so `P1.5D`, `PT1.5H`, `PT.5S`, and `PT1.S` all fail. Unit values are summed against a fixed `_SECONDS_PER` table (365d year, 30d month, 7d week).

**Two things the regex alone can't catch**, handled explicitly after the match, since every component is optional and the pattern would otherwise match them as empty:

- `"P"` and `"PT"` — rejected by requiring at least one component.
- `"P1DT"`, `"P1YT"` — a `T` separator with no time component after it.

**Return type**: `int` for whole-second durations, `float` only when the seconds component actually carried a fraction (the fraction detection is a `"." in value` check on the matched text, not a float round-trip, so `PT0.0S` correctly stays a float rather than collapsing to `int`).

**Two judgment calls worth confirming**, since the spec didn't pin them down:

- **Lowercase is rejected.** `"p1y"` and `"P1y"` raise. ISO-8601 designators are uppercase, and the spec listed "unknown characters" as invalid — but if the billing service has legacy rows with lowercase designators, adding `re.IGNORECASE` is the one-token change.
- **Non-string input raises `ValueError`, not `TypeError`.** `parse_iso_duration(None)` and `parse_iso_duration(5)` raise `ValueError`. `TypeError` is arguably more correct Python, but the stated goal is that bad data fails loudly and never reaches the database, and a caller wrapping this in `except ValueError` would otherwise let a `None` from a nullable column escape as an uncaught crash. Easy to flip if the call site handles types separately.

Signed durations (`P-1D`, `-P1D`) are rejected — the spec didn't mention them, and negative subscription intervals seem unlikely to be wanted here.
