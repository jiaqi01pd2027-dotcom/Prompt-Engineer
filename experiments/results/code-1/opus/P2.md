**Design:** one verbose regex with two alternatives — the week form `PnW`, or `P[nY][nM][nD][T[nH][nM][n[.n]S]]`. Lookaheads enforce "at least one component" after `P` and after `T`, so `P`, `PT`, and `P1DT` are rejected without post-hoc checks. Order and single-use of each unit fall out of the grammar. Returns `int` unless fractional seconds are present, then `float`. Non-str input raises `TypeError`; everything else invalid raises `ValueError` quoting the input.

Two strictness details worth knowing, both covered by tests:
- `[0-9]` rather than `\d`, because `\d` matches non-ASCII digits that `int()` will happily parse — `"P١D"` would otherwise return 86400.
- `\A`/`\Z` rather than `^`/`$`, because Python's `$` also matches before a trailing newline, so `"P1D\n"` would otherwise be accepted.

**Judgment call to confirm:** I treat the week form as exclusive (ISO 8601:2004), so `P2W3D` and `P1Y2W` raise. ISO 8601-1:2019 and `java.time` allow mixing; if you want that, it's a one-line regex change. I also reject the comma decimal separator (`PT1,5S`), reading it as an "unknown character" per your spec, though ISO permits it.
