**Approach:**
- Standalone weeks (`P2W`) are matched by a dedicated `P(\d+)W` regex (kept separate since weeks don't combine with other units in this spec).
- Everything else is matched by one regex enforcing correct designator order: `P(Y)?(M)?(D)?(T(H)?(M)?(S)?)?`, where only the seconds group allows a decimal point (`\d+(?:\.\d+)?`) — every other unit is `\d+` only, so a fraction anywhere else fails to match.
- Extra validation after the regex match: reject `"P"` (nothing matched at all), and reject a `T` present in the string with no H/M/S following it (catches `"PT"`).
- Conversion: years×365 + months×30 + days → total days → seconds, plus hours×3600 + minutes×60 + seconds. Returns `int` unless the seconds component has a fractional part, in which case it returns `float`.

**Verified via a self-contained test block** (run with `python3 iso_duration.py`, all passed):
- Valid: `P1Y2M3DT4H5M6S` → 36993906, `P2W` → 1209600, `PT1.5S` → 1.5, `PT36H` → 129600, `P1DT12H` → 129600 (confirms 1 day = 24h consistency).
- Invalid (all raise `ValueError`): missing leading `P`, empty `"P"`, `"P1S"` (time unit without `T`), `"PT"` (empty time part), `"P1.5Y"`/`"PT1.5H"` (fraction outside seconds), `"P1Y2W"` (week mixed with other units), `"P1X"` (unknown designator), `""`, `"PY"` (designator with no digits).
