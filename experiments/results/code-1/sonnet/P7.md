## Reasoning

**Grammar.** ISO-8601 duration strings have two mutually exclusive shapes:

```
P<weeks>W                                          (week form)
P[<n>Y][<n>M][<n>D][T[<n>H][<n>M][<n(.n)>S]]        (calendar form)
```

Key constraints I need to enforce:

1. **Leading `P` is mandatory.** No `P` → invalid.
2. **`P` alone is invalid** — there must be at least one component after it.
3. **Component order matters**: Y before M before D; H before M before S. A regex with sequential optional groups enforces this automatically — if the letters appear out of order, the full-string match fails.
4. **Time units require the `T` separator.** `P4H` looks plausible but is invalid because `H` never appears in the date part's grammar — it can only appear after `T`. I detect this by only ever trying to match H/M/S against `time_part` (the substring after `T`); if there's no `T`, the whole remainder must satisfy the *date* grammar (Y/M/D only), so `H` there fails to match and is correctly rejected.
5. **Dangling `T`** (`"P1DT"`, `"PT"`) is invalid — `T` present but nothing follows it. I check this explicitly: after splitting on `T`, if the tail is empty, raise.
6. **Fractions are legal only on seconds.** `"P1.5Y"` or `"PT1.5H"` look like they might work by analogy with `"PT1.5S"`, but only the seconds group's regex allows a decimal point (`\d+(?:\.\d+)?`); every other unit's group is `\d+` only, so a fraction there breaks the full match.
7. **Weeks cannot mix with anything else.** `"P2W"` is valid standalone; `"P2W3D"` is not. I special-case `W`: try `^\d+W$` first; if that fails but `W` still appears in the string, fail fast with a specific error rather than falling through to the date/time parser (which would also reject it, just less clearly).
8. **Unknown/extra characters** are caught because every parse uses `re.fullmatch` — any leftover character makes the match `None`.

**Strategy:** rather than one giant regex (hard to give good errors from and easy to accidentally allow fractions in the wrong slot), I split the work: peel off `P`, special-case the week form, then split on `T` into a date part and time part, and `fullmatch` each against its own tightly-scoped regex. Presence is tracked via `None` vs. `"0"` on capture groups so that legitimate zero-length durations like `"P0Y"` or `"PT0S"` are accepted rather than rejected as "empty."

## Code:

```python
import re


def parse_iso_duration(s: str) -> float | int:
    """
    Convert an ISO-8601 duration string to a total number of seconds.

    Accepted grammar:
        "P" <weeks> "W"
      | "P" [<n>"Y"] [<n>"M"] [<n>"D"] [ "T" [<n>"H"] [<n>"M"] [<n[.n]>"S"] ]

    Unit lengths: 1 year = 365 days, 1 month = 30 days, 1 week = 7 days,
    1 day = 24 hours. Fractions are only permitted on the seconds
    component. Raises ValueError for anything that doesn't fit the grammar
    above (missing/absent "P", empty "P", time units without "T", a
    dangling "T", misplaced fractions, weeks mixed with other units, or
    unrecognized characters).
    """
    if not isinstance(s, str) or not s.startswith("P"):
        raise ValueError(f"Invalid ISO-8601 duration: {s!r}")

    body = s[1:]
    if body == "":
        raise ValueError(f"Invalid ISO-8601 duration: {s!r} (empty 'P')")

    DAY = 24 * 3600

    # --- Standalone week form: P<n>W, nothing else allowed. ---
    week_match = re.fullmatch(r"(\d+)W", body)
    if week_match:
        return int(week_match.group(1)) * 7 * DAY

    if "W" in body:
        raise ValueError(
            f"Invalid ISO-8601 duration: {s!r} "
            "('W' weeks cannot be combined with other components)"
        )

    # --- Split into date part (before T) and time part (after T). ---
    if "T" in body:
        date_part, _, time_part = body.partition("T")
        if time_part == "" or "T" in time_part:
            raise ValueError(
                f"Invalid ISO-8601 duration: {s!r} (bad 'T' separator)"
            )
    else:
        date_part, time_part = body, None

    date_match = re.fullmatch(r"(?:(\d+)Y)?(?:(\d+)M)?(?:(\d+)D)?", date_part)
    if date_match is None:
        raise ValueError(f"Invalid ISO-8601 duration: {s!r} (bad date part)")
    y_g, mo_g, d_g = date_match.groups()

    h_g = mi_g = sec_g = None
    if time_part is not None:
        time_match = re.fullmatch(
            r"(?:(\d+)H)?(?:(\d+)M)?(?:(\d+(?:\.\d+)?)S)?", time_part
        )
        if time_match is None:
            raise ValueError(f"Invalid ISO-8601 duration: {s!r} (bad time part)")
        h_g, mi_g, sec_g = time_match.groups()

    if all(g is None for g in (y_g, mo_g, d_g, h_g, mi_g, sec_g)):
        raise ValueError(
            f"Invalid ISO-8601 duration: {s!r} (no components present)"
        )

    years = int(y_g) if y_g is not None else 0
    months = int(mo_g) if mo_g is not None else 0
    days = int(d_g) if d_g is not None else 0
    hours = int(h_g) if h_g is not None else 0
    minutes = int(mi_g) if mi_g is not None else 0
    seconds = float(sec_g) if sec_g is not None else 0.0

    total = (
        years * 365 * DAY
        + months * 30 * DAY
        + days * DAY
        + hours * 3600
        + minutes * 60
        + seconds
    )

    return int(total) if float(total).is_integer() else total
```

**Sanity checks** (traced through the logic above):
- `"P1Y2M3DT4H5M6S"` → `36993906` seconds (int)
- `"P2W"` → `1209600` (int)
- `"PT1.5S"` → `1.5` (float)
- `"PT36H"` and `"P1DT12H"` both → `129600` (int)
- `"P0Y"`, `"PT0S"` → `0` (accepted as valid zero-length durations)
- Rejected: `""`, `"P"`, `"PT"`, `"P1DT"`, `"P4H"` (no `T`), `"P1.5Y"`, `"PT1.5H"`, `"P2W3D"`, `"p1d"` (wrong case), `"1D"` (no leading `P`)
