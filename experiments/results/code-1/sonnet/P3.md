## Summary

Wrote `parse_iso_duration(s)` in `/private/tmp/claude-501/.../scratchpad/parse_iso_duration.py`.

**Approach:**
1. Require the string to start with `"P"` and have at least one more character.
2. If `"W"` appears in the body, require the *entire* remainder to match `^\d+W$` (weeks standalone, no fractions, no mixing with other designators) — return `weeks * 7 * 86400`.
3. Otherwise split on `"T"` (at most one occurrence; a trailing `T` with nothing after it, e.g. `"P1DT"`, is rejected).
4. Match the date part against `^(?:(\d+)Y)?(?:(\d+)M)?(?:(\d+)D)?$` — enforces integer-only Y/M/D in correct order, rejects unknown chars/duplicates/reordering.
5. Match the time part (if a `T` was present) against `^(?:(\d+)H)?(?:(\d+)M)?(?:(\d+(?:\.\d+)?)S)?$` — H and M must be integers; only S may carry a decimal fraction.
6. Sum using 365d/year, 30d/month, 7d/week, 24h/day → seconds, returning `int` unless a fractional-seconds value was present (then `float`).
7. Any regex failure, a `T` without following components, weeks mixed with other units, extra `T`s, or a missing leading `P` all raise `ValueError`.

**Verified via self-checks** (run with `python3 parse_iso_duration.py`, all passed):
- Valid: `"P1Y2M3DT4H5M6S"` → 36993906, `"P2W"` → 1209600, `"PT1.5S"` → 1.5, `"PT36H"` → 129600, `"P1DT12H"` → 129600, `"P0D"` → 0, `"PT0S"` → 0.
- Invalid (all raise `ValueError`): no leading `P`, empty `"P"`, `"P5H"` (time unit without `T`), `"P1.5Y"`/`"PT1.5H"`/`"PT1.5M"`/`"P2.5W"` (fraction outside seconds), `"P2WT1H"` (weeks combined with other units), `"P1D2Y"` (wrong order), `"PT"`/`"P1DT"` (dangling `T`), `"P1X"` (unknown char), `""`, `"P-1D"` (negative), `"p1d"` (lowercase).
